# domain/
> L2 | 父级: engine/app/CLAUDE.md

领域层：世界是什么（本体与掌故）、发生过什么（事件）、此刻怎样（聚合根折叠）、能做什么（裁决规则）、要什么样的存储（端口）。
纯 Python + Pydantic，不做 IO、不调大模型、不看时钟；唯一的外部依赖是共享内核 app/errors.py。

成员清单
models.py: 世界本体——实体 id 自带种类前缀（loc / chr / art / itm / ply）；Tier 是只比高下的有序等级；Attitude 是五档人情阶梯（敌视 −2 / 戒备 −1 / 漠然 0 / 友善 +1 / 信赖 +2，rank 比高下、step 按档移动并钳在两端，原有三值字面不动）；Era 关系结于何时（开篇 / 将至 / 后文）；Location（出入口映射 exits）；Character 三名分立：true_name 本名即主键（id 恒为 chr:{本名}，蓝图闸门拒收以称号篡位的主键）、titles 江湖称号、aliases 化名旧称，name / names 是派生属性，foreshadow 是从描述拆出的后文剧情（只供离线审阅，绝不进任何提示词），arrives_with 非空者后来才到场、T=0 不在任何场景；MartialArt 两道门：Acquisition 获取要求（师传 / 自悟、典籍、得门径之地、sealed 失传封存）与 Practice 修炼要求（作根基的武学、最低境界、相冲武学）；Item 至多一位物主、至多一个所在，两者皆空即下落不明（lost，孤儿，待播种期自愈），provenance 标明安放出自原著还是推断，portable 可否携带、hazard 险性（取到手即受伤）、use 用法 ItemUse（effect 疗伤 / 解毒 = Remedy、potency 1~3）、arrives_with；CharacterRelation 带 era（审计前一律开篇）；WorldBlueprint 是播种中间表示与最后闸门（重复 id、悬空引用、根基成环、主键不是本名、掌故不自洽一律拒收），另载 personas / facts 掌故，prerequisite_cycle 三色 DFS 供组装器复用
lore.py: 掌故本体——Persona 外显人设（character_id、likes / dislikes 每条 ≤16 字、worry 心事、sources 出处 ev:<块> / chunk:<块> 至少一条）、FactUnlock（TEACHING / LEVERAGE / HAZARD / MOTIVE + target_id）、Fact 见闻（id 形如 fact:<slug>、text ≤40 字、subject_ids、knower_ids 至少一人、unlock、sources）；lore_integrity_errors(bp) 是掌故的蓝图闸门：悬空引用、重复的人设与见闻、知情人须是主体本人 / 同门（同一门派）/ 与主体有关系边（物品的"本人"是物主与同处一地者，武学是身负者，地点是身在其中者）、unlock 须落在蓝图的一条边上（TEACHING ↔ 主体之一 KNOWS_SKILL、LEVERAGE ↔ target 与另一主体有 HAS_RELATION、HAZARD ↔ 带 hazard 的物品、MOTIVE ↔ 有人设者）；"不得照抄原文"需要原著全文，由离线 ingest 闸门守
progression.py: 渐进式状态的两把尺——Mastery 火候（熟练度 × 悟性系数 → 初窥门径 / 略有小成 / 融会贯通 / 炉火纯青 / 登峰造极，effective_tier 火候不到境界打折，FOUNDATION 作根基须略有小成）、Guidance 修习方式与 GAIN 每次所得、aptitude_for 根骨天定的悟性；Vitality 伤势（MAX_HP 气血、vitality 分档、REST_GAIN 调息所得）；内部整数、对外语义，事件只记"练了多少"，"练到哪一步"永远现算；火候封顶（初窥门径最高三流、略有小成最高二流、融会贯通最高一流），gain() 让一次修习所得随武学境界折算（三流 ×1、二流 ÷1.5、一流 ÷2、绝顶 ÷3）——实测捡到绝顶秘籍读两回就成一流高手，此后要练十来回
combat.py: 模糊裁决的硬轨——CombatOutcome（得手 / 相持 / 轻伤 / 重伤 / 毙命）与 HP_BANDS 气血区间；assess 依境界差、性情、伤势圈出可裁区间 Stakes（admissible + canonical，境界差 + 伤势加码 ≥ 3 且对方狠辣才算极端找死，毙命才入区间；seize_id 夺物得手即易手之物，target_id 与另两路同口径）；settle 把地下城主的 CombatProposal 钳进区间与气血带（出界取确定性裁决、非毙命至少留一口气），CombatRuling.adopted 标明速写是否作废
intent.py: 命令语言 ActionType（MOVE / OBSERVE / TALK / ATTACK / TAKE / GIVE / LEARN / REST / USE / INVALID）、Approach 手段（寻常 / 武力 / 言辞 / 人情 / 计谋 / 潜行 / 借势）、Aim 所图（制人 / 夺物 / 脱身 / 求艺 / 打探 / 结交 / 化解 / 讨要 / 示警）与 PlayerIntent（action_type / target_entity / item_used / skill_used / narrative_style / reason / approach 缺省寻常 / aim / topic 话题）；LEARN 一个动作涵盖入门与精进，USE 是服药敷药；指称与话题超长或空串时规整而非拒收；(动作, 手段) 的兼容表与所图推断在 approach.py；放在 domain 而非 application，因为裁决规则消费它，领域不得反向依赖应用层
approach.py: 「招」的词汇——Route（战 / 交 / 暗 / 定）、Row（兼容表的行，TAKE 分地上之物与他人之物）、Cell（路线 + 隐含所图 + 说法 + 师父不肯时的退路）、MOVES 封闭兼容表（逐格照搬 PROPOSAL_v2 §3.3）、AIMS 各动作配得上的所图、normalize（表外手段退回寻常、所图不配置空、话题落不了地置空，幂等；物在谁手与话题能否落地由 rules 判定后作参数交进来）、infer_aim（说了的照说 → 格内隐含 → 带话题打探 → 敌视戒备化解 → 结交）
outcomes.py: 另两路结局词汇（与 combat.CombatOutcome 并列，都由对玩家最有利到最不利）——SocialOutcome 交涉（如愿 / 松动 / 无果 / 碰壁 / 翻脸）、CovertOutcome 暗中行事（按后果由轻到重：无痕 / 未遂 / 败露 / 失手）；单独成模块以断环：events 用它们，social / covert 又从 events 导入
social.py: 交涉硬轨（与 combat 对称）——SocialStakes（npc、所图、手段、交情、性情、分数、admissible / canonical、所求之物 subject_id、筹码 leverage_ids、求艺所需人情 need）、assess_social（交情 rank（威逼改看境界差，被制住 +2）+ 性情 + 筹码 − 难度 − 纠缠 − 虚张声势 → 五档区间；硬约束剔格：够不着无如愿、只有武力 / 计谋 / 借势会激人翻脸、仁厚不翻脸）、settle_social（出界取确定性裁决）、effects（定案 → Parleyed + FactLearned / ItemTransferred / RelationChanged：阶梯每次至多一档、交涉止于友善 CAP、威逼得逞畏而不服、翻脸直落敌视、求艺从不传功、永不伤人）
covert.py: 暗中取物硬轨——CovertStakes（失主、物、手段、失主态度、差额 margin、admissible / canonical）、assess_covert（境界差；失主敌视或戒备 −1、骗取信你之人 +1、失主被制住 +2；按无痕 / 未遂 / 败露 / 失手连续切片）、settle_covert、effects（Maneuvered 恒入账；无痕易手、败露易手且失主敌视、失手只结仇；永不伤人）
stakes.py: 统一赌注门面——AnyStakes（combat.Stakes | SocialStakes | CovertStakes，同口径 admissible / canonical / contested / target_id）、Outcome、Proposal（通用提议：结局 + 扣减）、Ruling、settle_any（分派三路 settle，出界取确定性裁决；CombatProposal 照收）、route_of、Risk（稳妥 / 有险 / 凶险）与 risk_of（只看区间最坏的一端；无赌注即稳妥）
threads.py: 心事线索——Thread（对象、所图、所求、已试手段、进展、所需人情、尝试次数）、THREADS_MAX=6、fold（交涉不如愿 / 暗取未得手 / 求教被拒开启或推进，驳回不计次数；如愿、到手、得其点拨、结交到友善、化解到漠然即了结；新者在前、满了请走最旧的）、pursuing
reputation.py: 名声（取代 rules 的 _ripple）——ripple（受害者敌视；只认开篇羁绊、只波及在场且行动自如的目睹者：休戚与共者敌视、仇家升一档至多友善）、kinship（按 BondView.lead 取称谓：上首见徒弟挨打是「你打伤其得意门徒某某」）、STRUCK；RelationChanged.basis 记称谓所据的关系
events.py: 十四种不可变领域事件（PlayerSpawned 含悟性 / Moved（fleeing 标明夺路而逃，旧账缺省为自行离去）/ ItemTransferred / SkillPracticed 熟练度所得 / SkillExecuted（approach 手段）/ HealthChanged 气血涨落（source：blow 伤人 / rest 调息 / item 服药）/ Conversed（topic_id）/ RelationChanged（basis 关系称谓或缘由类别）/ ActionFailed（unlock 怎样才行、aim / approach）/ PlayerDied / Parleyed 交涉（npc、所图、手段、SocialOutcome、leverage_ids 由领域选出的筹码）/ FactLearned 得知见闻 / ItemConsumed 用掉随身之物 / Maneuvered 暗中取物（CovertOutcome））；P1 新字段一律有缺省值；AnyEvent 按 type 判别、EVENT_ADAPTER 负责编码；decode_event 是账本唯一的读出入口，先经 UPCASTERS 把旧词汇上抛（SkillLearned → 一次融会贯通的 SkillPracticed、「受挫」→「轻伤」、没有 source 而 cause=="调息疗伤" 的 HealthChanged → source="rest"）再校验，账本字节一字不改；EventEnvelope 携带流内版本与记录时间，事件本体不含时间以保持裁决确定性
aggregates.py: PlayerState（位置、来路 came_from、逃离过的险地 fled_from、悟性、气血、生死、practice 熟练度之和、item_holders 物品易手覆盖、subdued 制住之人、attitudes 人情、attitude_causes 人情的缘由（最近一次 RelationChanged.cause）、focus 焦点与 focus_fresh（上一个主动作是否正与 focus[0] 打交道：自行离去、调息（HealthChanged.source=="rest"，服药不算）、闭门苦练之后即不新鲜，交手余波与碰壁不算）（近来亲手打过交道的人与物，新者在前、至多 4 个：出手的对手、攀谈与交涉的对方、易手另一端的人与那件东西、暗取的失主与那件东西、修习所凭的师父或典籍；人情涟漪的目睹者、驳回的原话、去过的地方都不算）、threads 心事线索（至多 6 条，threads.fold）、known_facts 已知见闻、consumed 用掉之物、recent_approaches 近来出招的手段（至多 4 个）、attempts 对每个对象出过几次有赌注的招（FortuneResolver 的种子）；skills / inventory（排除用掉之物）/ mastery / vitality 皆派生而非另存）、evolve 纯函数折叠（熟练度与气血只做加法，气血钳位，归零不等于死）、Player 聚合根（apply 吸收事实 / from_history 校验版本连续地重放 / replay 即 reduce / spawn 定下悟性 / ensure_alive 永久死亡之门 / mastery 武学等级 / decide 携地下城主对任一路赌注的提议委托裁决）；一位玩家的平行世界就是这一个聚合的一致性边界
snapshot.py: 局部真理快照 LocalSnapshot（位置、出路（hostile_ahead 去处有仇人）、在场者及其称号 / 所会 / 羁绊（BondView 带 era 与 lead 本人是否上首）/ 外显人设 PersonaView、可见之物及持有者与物主与物性（portable / hazard / use）、此情此景可知的武学及其获取 / 修炼要求、知情人在场的见闻 FactView、玩家的熟练度 / 悟性 / 气血原始值与现算的 mastery / vitality、labels 名称表）；P1 新字段都有缺省值，图谱实现不填照样构造；集合字段在构造时按固定键排序（缺了新字段的原始字典按缺省值排序），任何图谱实现得到逐字段相等的值；referenced_ids 列出 labels 必须覆盖的全部 id（含见闻的主体、知情人与 unlock 目标）
rules/: 裁决核心（Decider）包，门面 adjudicate / stakes（三路赌注之一）/ decide（经 settle_any 定案）/ normalized 与 RULES 注册表在 __init__，base（裁决结果带路线与所图、名称与话题落地、境界折算、仇人判据）/ physical（静观、移动、取物按物性与手段分路、险物伤手、服药、调息、天道）/ talk（交谈与交涉、赠物与物归原主直升信赖）/ martial（出手与夺物、修习、求艺不成改走交涉、逃向无仇之处）/ parley（交与暗两路的接线：筹码、待学的见闻、求教门槛）分管，地图见 rules/CLAUDE.md
ports.py: 端口——EventStore（原子追加 + 乐观并发 / 按版本读）、WorldReader（局部快照 / 出生点 / 名称表）、WorldProjector（幂等投影 / 检查点 / 抹去覆盖层）、WorldSeeder（播种 / 是否已播种）、NarrativeMemory（以玩家 + 版本为主键幂等写入 / 按玩家与版本上限召回）与 MemoryRecord；图谱端口按读、投影、播种拆分（接口隔离）
__init__.py: 包标识

依赖说明
- rules/ 只在类型标注里引用 aggregates.PlayerState（TYPE_CHECKING），aggregates 运行期导入 rules 门面：两者互引而不成环
- models 运行期导入 lore（Persona / Fact 是蓝图字段），lore 只在类型标注里引用 models：不成环；outcomes 位于 events 之下，social / covert 由此导入而不成环
- approach 只认意图与人情、不读快照（rules 依赖它，反之不然）；social / covert 只吃纯数值输入，从快照取事实是 rules/parley 的事；reputation 读快照，只在类型标注里引用 PlayerState
- 裁决只看两样东西：快照（他人与地理的物理事实）与玩家状态（自身的逻辑事实）；回合编排保证二者版本一致后才调用
- 依赖方向：lore ← models ← progression ← combat；intent 与 outcomes 自立；models / combat / intent / outcomes ← events；models / lore / progression ← snapshot；intent / models ← approach；events ← social / covert / threads；approach / combat / social / covert ← stakes；events / snapshot ← reputation；events / snapshot / approach / stakes / reputation / threads ← rules ← aggregates（另依赖 stakes / threads）；combat 与 progression 都是纯函数，聚合根、快照与规则共用同一套折算
