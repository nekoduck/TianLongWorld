# infrastructure/
> L2 | 父级: engine/app/CLAUDE.md

基础设施层：实现 domain 与 application 拥有的端口，并承载 World Seeding 管道。这里是唯一允许出现 asyncpg / neo4j / qdrant-client / HTTP 的地方。
播种分七段且彼此解耦：抽取器读书（非确定；本项目由 Claude 子代理经 export / ingest 担任，付费大模型只在 seed --use-llm 时上场）→ 组装器定案（确定）→ 图谱自愈（据常识安放孤儿，经闸门、标明推断）
→ T=0 审计（关系 era、描述拆出后文剧情、物性、后来才到场）→ 掌故（人设、见闻与人群）→ 地理（出路的方位 / 交通方式 / 耗时，地标与名胜）→ Cypher 编译（确定）；审计、掌故与地理只由子代理经 export / ingest 撰写，根本没有大模型这条路。
中间表示 WorldBlueprint 是正典，Neo4j 与内存图谱都只是它的投影——一切修补（含自愈、审计、掌故、地理）都作用于蓝图，再经 seeder 写图，绝不直接改图；
四份离线缓存（healing.json / audit.json / lore.json / geography.json）各带版本，后三份另带蓝图指纹，assemble / extract 依次零费用自动套用。

依赖说明
- blueprint_assembler 只在类型标注里引用 knowledge_extractor 的 ChunkExtraction（TYPE_CHECKING），运行期由后者导入前者（含 CanonEventKind），不成环
- graph_linter 依赖 knowledge_extractor（T0_ANCHOR / escape_markup），不依赖组装器：它只读写蓝图，任何来源的蓝图都能体检与自愈
- canon_audit 依赖 knowledge_extractor（语料、切块、缓存路径、抽取契约）与 blueprint_assembler 的泛称词表与"描述不是名字"判据（专名名录与组装器同一口径）；lore_gate 依赖 canon_audit（证据库、专名判据、自由文本闸门、与后文冲突的判据）与 domain/lore 的掌故闸门；两者都不依赖 graph_linter
- 套用顺序是 自愈 → 审计 → 掌故 → 地理：掌故的指纹覆盖审计定下的 era 与物性；地理只认地点名字与出口拓扑，不进掌故与审计的指纹（lore_fingerprint 排除 passages / sights）；graph_linter、canon_audit、lore_gate 重建蓝图时原样带过掌故与地理注记，seed 自愈之后仍按缓存重新套用审计、掌故与地理（安放改了所在，掌故指纹可能随之作废）
- geo_gate 依赖 canon_audit（证据库、自由文本闸门、resolve、parse_json、one_line）、knowledge_extractor（T0_ANCHOR / escape_markup）与 domain/geography（Passage / Sight / ways / geography_errors），不依赖 lore_gate 与 graph_linter；cypher 与两套图谱同读 domain/geography.ways
- 播种的时间切片是 T=0（原著开篇）：v6 契约让抽取器把开篇之后的变化写成事件、组装器据事件否决被污染的开篇状态；
  v5 及更早的缓存没有事件，仍按"首次登场即开篇、列表取并集"组装，用 --max-chunks 只取开篇可得到更忠实的开局
