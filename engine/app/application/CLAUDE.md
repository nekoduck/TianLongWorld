# application/
> L2 | 父级: engine/app/CLAUDE.md

应用层：用例编排。它把命令翻成领域调用、把胜负未定之事（出手 / 交涉 / 暗中）交给一席裁决（文本请地下城主、点选交给气运）、把事件推给投影、先算菜单再把快照与端倪交给大模型渲染，
自身不含业务规则（规则与可裁区间在 domain/rules/、domain/combat.py、social.py、covert.py、stakes.py）。
对外边界是 bus.py：命令进、回合消息的异步流出；对内只依赖 domain 的端口与本层的 LLMClient 抽象。

成员清单
ports.py: LLMClient 抽象（complete 一次性补全 + 带默认实现的 stream 流式补全）与 JsonSchema 别名；端口上没有任何写世界的方法
bus.py: 命令 SpawnPlayer / ResumePlayer（quiet：只重新接上，不复述此景、不调大模型）/ SubmitText / ChooseOption，回合消息 SessionOpened / TurnResolved（意图 + 事实白描，先于叙事送达）/ NarrationDelta / TurnCompleted（全文、选项、PlayerStatus、game_over），PlayerStatus 只有语义标签（境界、伤势 health、武学写作「北冥神功（略有小成）」），另有 bonds（Bond{name, attitude, cause}）与 pursuits（Pursuit{label, note}）两栏，缺省为空，旧客户端照读；CommandHandler 抽象与 CommandBus（按命令类型分派，重复注册即报错）
handlers.py: TurnPipeline 一回合的完整生命周期——命令侧持弱引用玩家锁：重放事件流 → 自愈投影 → 快照（版本与位置须与聚合一致）→ 死者在解析前即拒 → [Parse] → [Validate] rules.stakes 圈出可裁区间（出手 / 交涉 / 暗中）→ [Resolve] 一席裁决 AdjudicationSlot.resolve(…, clicked)：自由文本请地下城主、点选（ChooseOption 处理器传 clicked=True）交给气运、结果已定谁也不请 → [Event] Player.decide 携提议定案（stakes.settle_any 钳进区间）、乐观并发追加 → 同步投影图谱；速写只在结局被采纳（adjudication.adopted_sketch，三路都认）时经 NarrationRequest.hint 传给渲染器，不入事件、不入记忆，否则作废；重伤夺路而逃（Moved.fleeing）的回合把交手前的快照经 NarrationRequest.fled 交给渲染器；查询侧：新快照 → 记忆召回（两路、原话优先：原话 + 玩家名一路，焦点实体 + 在场者本名一路）→ TurnResolved（facts 滤掉空串白描）→ [Options] 先于叙事算出，narrator.hooks(菜单) 作端倪经 NarrationRequest.hooks 交给说书人 → [Render] 流式叙事 ∥ 记忆写入 → TurnCompleted（状态栏的人情 / 心事两栏：status.referenced 列出要取名的 id，快照与交手前快照之外缺的名字一回合只向 reader.labels 取一次）；出生点按 crc32(player_id) 确定性分配或按名指定；四个处理器只决定"意图从哪来"（自由文本经解析器，选项按当前快照重算后核验 id，不经大模型）；记忆召回各多取一倍再按字面去重；续前缘与出手共用玩家锁（续上的必是落账之后的局面），quiet 续接不复述、不调大模型，只回选项与状态（断线重连、选项过期）；在场者的恩怨缘由（PlayerState.attitude_causes）经 NarrationRequest.causes 交给渲染器；死者伤势栏写「气绝」
intent_parser.py: 三道防线——WorldviewGuard 词表在调用大模型之前判 INVALID（刻意不收单字「枪」）、提示词要求大模型对违背世界观者判 INVALID、规则只认图谱实体；IntentParser 模板方法（守卫 → 解读 → 对产出的指称与话题 target / item / skill / topic 再守卫，两道检查都先剔除撞上禁词的场景正名 scene_names 与 WorldviewGuard.for_canon 收录的原著撞词正名——原著的「金针渡劫」在哪儿都不被「渡劫」误杀）；INTENT_SCHEMA 只有形状（domain/intent 不写 docstring），说明全在 INTENT_SYSTEM：LEARN 涵盖入门与精进、REST 调息疗伤独立成动作（练功疗伤以疗伤为准）、USE 服药敷药（服药疗伤以 USE 为准）、七种手段与九种所图各一句判据（「用于 / 见于」由 approach 兼容表生成，表一改提示词跟着改）、topic 话题指称（说话的对象不进 topic）、撂话离场是 MOVE（话只化进笔墨）；场景词表的人物带称号与别名、已会武学带火候；LLMIntentParser 带场景词表与输入转义、结构化输出、重采样后兜底 INVALID、LLMError 透传（回合不写任何事件）；HeuristicIntentParser 离线动词 + 关键词 + 场景词表解析：手段按 借势 > 人情 > 武力 > 计谋 > 潜行 > 言辞 认关键词并经 _fit 按兼容表退回寻常（偷袭是出手不是潜行）、打探的话题取中心词且须经 rules.ground 落得了地（落不了地只是闲谈）、威逼是 TALK×武力（点名对方手里的东西即讨要）、劝 / 说和 / 赔罪是言辞化解、服 / 敷 / 吃 + 点名之物是 USE（先于调息）、开口要他人之物是言辞讨要、引号里的话不算动作、借势的靠山不是说话的对象、人与物取最先点名者；调息疗伤先于修习判定，但句中有在场之人与出手动词时是出手——「趁龚光杰调息偷袭他」；点名不在场景里的东西照抄原话交给规则驳回
options/: 动态选项生成器（显著性菜单）包，地图见 options/CLAUDE.md——五类候选源（Thread 换个手段 / Person 一人身上的诸般招 / Ground 地上可携之物与疗伤之药 / Self 静观调息修习 / Exit 出路）经 rules.adjudicate 过滤，措辞按意图哈希挑变体，P0 的打分与席位全保留（MMR 冗余改为累加），同一对象至多两席，每席带 why（≤12 字）与风险档（risk_of(rules.stakes)，确定之事稳妥）；门面 `from app.application.options import ActionOption, OptionCategory, OptionGenerator` 不变
narrator.py: NarrationRequest（含地下城主速写 hint、夺路逃离的交手现场 fled、在场者的恩怨缘由 causes、本回合菜单的端倪 hooks）、hooks(options)（选项 → 「标签（why）」，至多 HOOKS_MAX=4 条，按结构化 Protocol 只认 label / why）、hard_prompt（fled_scene / truth_snapshot / known_facts / settled_facts / gm_sketch / memories / hooks / player_input，在场者带称号与外显人设「好…；恶…；心事…」、玩家带伤势与武学火候，每个插值逐值转义；<known_facts> 只放 known=True 的见闻，known=False 的见闻是打探的标的，绝不进任何提示词）、NARRATOR_SYSTEM（只渲染不裁判、速写只可扩写招式不可改判、不得引入快照之外的人物物功地、玩家声称持有却不在行囊与武学里的东西根本不存在、举止合乎伤势、不写数值；铁律 1 / 2 / 5 许 <hooks> 作端倪露在场面里（神色、目光、只言片语、物件所在），不许写成已发生的结果、不许替玩家行动、不许列成选项或向玩家发问）、LLMNarrator 流式、TemplateNarrator 离线白描（速写作一句白描，紧随那一招的事实）、FallbackNarrator（主渲染失败：一字未出则整段白描，已出半截则补断语与白描）；铁律经真实整局实测补强（没有「来到某地」就仍在原地、facts 之外的变化不写、行囊里的东西没易手就仍在身上、不照抄标签词），在场者武学带类别、人物行在态度之后附「恩怨：…」（交手现场是交手前的样子，不附）；夺路而逃的回合交手现场另作 <fled_scene>
resolution_agent.py: 模糊裁决引擎（地下城主）——Resolution（提议 Proposal | CombatProposal + 速写 + 出处：规则 / 地下城主 / 气运）、Resolver 抽象（resolve 接收三路赌注之一 AnyStakes）、CanonicalResolver（空提议，领域取确定性裁决）、CombatResult / SocialResult / CovertResult（结局认枚举名也认中文；三路共用速写闸门：超 80 字或夹带 JSON / 英文 / 数字整句作废）、gm_system() 与 GM_SYSTEMS（共用铁律：只裁什么、0 号结局含义、末条只出 JSON + 每路一段说明，各段由 briefs/ 持有；出手一路逐字仍是 v3 铁律，GM_SYSTEM 即它）、LLMResolutionAgent（按路线出简报、铁律与 schema；不 contested 不花钱、区间外或不合契约即重采样、时间预算 LLM_RESOLUTION_BUDGET 管整场裁决、任何 LLMError 与意外都退回兜底，绝不抛错、不退避重试）、FortuneResolver（点选回合的气运，不调大模型：种子 sha256(玩家 | 对象 | 对该对象的尝试次数)，不取版本号；canonical 60% / 好一格 25% / 差一格 15%，越界或差一格落进 GRAVE（毙命 / 翻脸 / 败露 / 失手）都留在 canonical，出手的扣减在所选结局的气血带里由同一颗种子取值，仍经 settle_any 钳位）；combat_brief / verdict_schema / MEANING 旧导入路径照旧可用
adjudication.py: 一席裁决 AdjudicationSlot(resolver, fortune)——无赌注或不 contested 返回 None（零调用）；点选交给气运（FORTUNE_ON_CLICK 关掉时为 None，即 canonical）；自由文本交给地下城主，每回合只调它一次（它内部的重采样是它自己的事）；adopted_sketch() 三路都认：入账的 SkillExecuted / Parleyed / Maneuvered 的 outcome 正是提议的结局，速写才交给叙事，否则作废
briefs/: 地下城主简报包——__init__ 门面（brief / schema 按路线分派，Section / SECTIONS 是每路一段铁律，outcome_schema 只列可裁结局）；combat.py（v3 战况简报、verdict_schema、MEANING 原样挪来，另持有共用工具 safe / join）；social.py（对方的本名称号、门派、境界、性情、态度与恩怨缘由、外显人设、是否被制住、T=0 描述，所图、手段、标的、筹码、可裁结局及含义；如愿的含义随所图而变，松动升不升人情问效果表）；covert.py（失主、物、手段、境界差与情势、可裁结局及含义；不写险性）。三份简报都只用快照的 T=0 事实：foreshadow 永不进；打探的标的只写「此人所知的一桩事」，未知见闻的正文永不进；逐值转义
chronicle.py: describe(event, labels, player_name) 事件 → 一句确定性白描（夺路而逃写作「夺路逃离某地，来到某地」；人情五档各有措辞，敌视「心生敌意」/ 戒备「心存戒备」/ 漠然「不再放在心上」/ 友善「生出好感」/ 信赖「深为信赖」；交涉「以言辞向某人求艺，对方口风已松」、见闻「从某人处打听到「…」」、用物「以某物疗伤」、暗中取物「以潜行暗取某人的某物——未能得手，好在无人察觉」；服药那条 HealthChanged(source="item") 白描为空串（ItemConsumed 已说了服药），调用方一律滤掉空串）；供 TurnResolved.facts、叙事的 settled_facts 与长线记忆语料共用——记忆里只存白描不存散文，幻觉（含地下城主的速写）进不了记忆；titled「段延庆（恶贯满盈）」与 known_arts「北冥神功（略有小成）」是称呼与火候的唯一写法，状态栏、Hard Prompt 与战况简报共用
projections.py: ProjectionCoordinator——publish 同步投影图谱（强一致：下一步裁决依赖它）、heal 检查点落后则从事件流追平、超前则抹去重放、chronicle 尽力写入长线记忆（失败只记日志）、rebuild 运维用整体重建两份投影；记忆写入滤掉白描为空串的事件
status.py: 状态栏附栏纯函数——referenced(state) 列出需取名的 id（非漠然者 + 前三条线索的对象与标的，见闻 id 一律不取，正文连名字表都不进）、bonds(state, snap, names) 人情一栏（态度非漠然者，在场者优先、再按 |rank| 降序、再按 id，至多 6 条，缘由取 attitude_causes）、pursuits(state, names) 心事一栏（新者在前至多 3 条，「求艺 · 晓风拂柳」式标签——打探只写对象「打探 · 左子穆」绝不写见闻正文，note「口风已松；已试：言辞；须友善」）；handlers 一回合一次 reader.labels、两次调用，世界不变则逐字不变
__init__.py: 包标识

依赖说明
- 本层的 LLMClient 抽象也被 infrastructure 的播种管道与厂商客户端引用：外层依赖内层，方向正确
- 地下城主只产出提议（出手 CombatProposal，交涉与暗中 Proposal）：定案永远是领域的 stakes.settle_any，区间外的结局与气血带外的扣减都被钳回；它只为自由文本回合发言，在命令侧玩家锁里同步调用；点选回合由 FortuneResolver 确定性地取值，不花钱，也不比确定性裁决更凶险
- 一回合至多三次大模型调用（意图 + 地下城主 + 叙事）：点选回合只有叙事，结果已定的文本回合只有意图与叙事；唯一的例外是地下城主越界或不合契约时的一次重采样（LLMResolutionAgent attempts=2，仍在 LLM_RESOLUTION_BUDGET 之内）
- 选项是 (玩家状态, 快照) 的纯函数：点选时重算即可核验，不需要任何会话缓存，多进程部署天然一致；焦点与恩怨都由事件折叠进 PlayerState，不另存
- 菜单先于叙事算出：叙事只拿到「标签（why）」作端倪（<hooks>），选项的意图永远不进提示词；菜单变了叙事才可能变，叙事从不反过来影响菜单
