# application/
> L2 | 父级: engine/app/CLAUDE.md

应用层：用例编排。它把命令翻成领域调用、把获准之举的物理边界交给一席裁决（文本在胜负未定或挂着时钟时请地下城主推演、点选在胜负未定时交给气运）、把定案交给世界时钟算出这一招之后的心跳（余波 / 光阴 / 扩散 / 生态）、把事件推给投影、先算菜单再把快照与端倪交给大模型渲染，
自身不含业务规则（规则与可裁区间在 domain/rules/、domain/combat.py、social.py、covert.py、stakes.py，世界物理在 domain/heartbeat.py）。
对外边界是 bus.py：命令进、回合消息的异步流出；对内只依赖 domain 的端口与本层的 LLMClient 抽象。

成员清单
ports.py: LLMClient 抽象（complete 一次性补全 + 带默认实现的 stream 流式补全）与 JsonSchema 别名；端口上没有任何写世界的方法
bus.py: 命令 SpawnPlayer / ResumePlayer（quiet：只重新接上，不复述此景、不调大模型）/ SubmitText / ChooseOption，回合消息 SessionOpened / TurnResolved（意图 + 事实白描，先于叙事送达）/ NarrationDelta / TurnCompleted（全文、选项、PlayerStatus、game_over），PlayerStatus 只有语义标签（境界、伤势 health、武学写作「北冥神功（略有小成）」），另有 bonds（Bond{name, attitude, cause}）与 pursuits（Pursuit{label, note}）两栏、眼前的暗流 clocks（ClockInfo{name, kind, progress, maximum}，至多 4 只，id 与挂处不下发）、名望 renown（语义标签）与时辰 time（「第一日·辰正」，取快照的 time_label，死者停在最后时刻），缺省为空，旧客户端照读；CommandHandler 抽象与 CommandBus（按命令类型分派，重复注册即报错）
handlers.py: TurnPipeline 一回合的完整生命周期——命令侧持弱引用玩家锁：重放事件流 → 自愈投影 → 快照（版本与位置须与聚合一致）→ 死者在解析前即拒 → [Parse] → rules.command 定下这一招花几刻（Command.time_cost：驳回一刻、同一处所之内走动一刻、换处所四刻、调息修习八刻）→ [Validate] rules.envelope 圈出物理边界（三路赌注或 FIXED，驳回为 None）→ [Resolve] 一席裁决 AdjudicationSlot.resolve(env, before, state, intent, said, clicked=…)：自由文本在胜负未定或此景挂着时钟时请地下城主推演、点选（ChooseOption 处理器传 clicked=True）在胜负未定时交给气运、其余谁也不请 → [Event] Player.decide 携提议过闸定案（resolution.settle：推出结局、钳位、补足代价、时钟坍缩） → 世界心跳 WorldClock.advance(command, before, 定案前的状态, 定案)（余波：交手的往事与痕迹、人群溃散、公开之事成为消息 → TimePassed → 消息沿路扩散 → 黎明的风化与顺手牵羊；死者没有心跳）→ 定案与心跳一并乐观并发追加（时钟四事件 / FactEmerged / RenownChanged / 世界心跳七事件同一批入账；静观、沉思也写事件——只有 TimePassed）→ 同步投影图谱；推演到叙事只有入账之物一条路：白描进 turn_resolved 与 <settled_facts>，新快照的 clocks / emerged 进 <clocks> / <emerged>，没有散文旁路；重伤夺路而逃（Moved.fleeing）的回合把交手前的快照经 NarrationRequest.fled 交给渲染器；定案里有 Moved（含夺路而逃）的回合，出发前的快照与那条 Moved 的 motivation 经 narrator.recollect 成为短期记忆 NarrationRequest.recollection（刚离开之地、眼中所见、此行所为），没跨地方的回合为 None；NarrationRequest.motivation 恒取 PlayerState.motivation；查询侧：新快照 → 记忆召回（两路、原话优先：原话 + 玩家名一路，焦点实体 + 在场者本名一路）→ TurnResolved（facts 滤掉空串白描）→ [Options] 先于叙事算出，narrator.hooks(菜单) 作端倪经 NarrationRequest.hooks 交给说书人 → [Render] 流式叙事 ∥ 记忆写入 → TurnCompleted（状态栏的人情 / 心事两栏：status.referenced 列出要取名的 id，快照与交手前快照之外缺的名字一回合只向 reader.labels 取一次；眼前的暗流 status.clocks(快照)、名望 status.renown(状态) 与时辰 snap.time_label 随状态栏下发）；出生点按 crc32(player_id) 确定性分配或按名指定；四个处理器只决定"意图从哪来"（自由文本经解析器，选项按当前快照重算后核验 id，不经大模型）；记忆召回各多取一倍再按字面去重；续前缘与出手共用玩家锁（续上的必是落账之后的局面），quiet 续接不复述、不调大模型，只回选项与状态（断线重连、选项过期）；投胎与续前缘（含 quiet）不走时间——它们不是玩家的命令；构造参数 clock 缺省为空 Atlas 上的 WorldClock（时间照走、消息只留在发源地），组合根交给它正典的 Atlas；在场者的恩怨缘由（PlayerState.attitude_causes）经 NarrationRequest.causes 交给渲染器；死者伤势栏写「气绝」
intent_parser.py: 三道防线——WorldviewGuard 词表在调用大模型之前判 INVALID（刻意不收单字「枪」）、提示词要求大模型对违背世界观者判 INVALID、规则只认图谱实体；IntentParser 模板方法（守卫 → 解读 → 清空非 MOVE 的此行所为 → 对产出的指称、话题与此行所为 target / item / skill / topic / motivation 再守卫，两道检查都先剔除撞上禁词的场景正名 scene_names 与 WorldviewGuard.for_canon 收录的原著撞词正名——原著的「金针渡劫」在哪儿都不被「渡劫」误杀）；INTENT_SCHEMA 只有形状（domain/intent 不写 docstring，model_json_schema 自动带上 THINK 与 motivation），说明全在 INTENT_SYSTEM：LEARN 涵盖入门与精进、REST 调息疗伤独立成动作（练功疗伤以疗伤为准）、USE 服药敷药（服药疗伤以 USE 为准）、THINK 沉思（回想、盘算、权衡，不动手不开口不挪步）、七种手段与九种所图各一句判据（「用于 / 见于」由 approach 兼容表生成，表一改提示词跟着改）、topic 话题指称（说话的对象不进 topic）、motivation 此行所为（只在 MOVE 时写去找谁、去做什么，≤24 字，没说即空串、不替玩家编来由，别的动作一律空串）、撂话离场是 MOVE（话只化进笔墨），示例逐条带 motivation，含沉思与带所为的移动；场景词表的人物带称号与别名、已会武学带火候；LLMIntentParser 带场景词表与输入转义、结构化输出、重采样后兜底 INVALID、LLMError 透传（回合不写任何事件）；HeuristicIntentParser 离线动词 + 关键词 + 场景词表解析：手段按 借势 > 人情 > 武力 > 计谋 > 潜行 > 言辞 认关键词并经 _fit 按兼容表退回寻常（偷袭是出手不是潜行）、打探的话题取中心词且须经 rules.ground 落得了地（落不了地只是闲谈）、威逼是 TALK×武力（点名对方手里的东西即讨要）、劝 / 说和 / 赔罪是言辞化解、服 / 敷 / 吃 + 点名之物是 USE（先于调息）、开口要他人之物是言辞讨要、引号里的话不算动作、借势的靠山不是说话的对象、人与物取最先点名者；调息疗伤先于修习判定，但句中有在场之人与出手动词时是出手——「趁龚光杰调息偷袭他」；沉思的关键词（想想 / 寻思 / 沉思 / 盘算 / 回想 / 思索）只在别的动作都没命中时判 THINK（「回想龚光杰那一剑」不是找他说话，「寻思片刻，南下而去」是移动）；MOVE 的此行所为按结构切分——用出口名（出路名或去处名）定位去处、取其后到句末的一段（「去大理城找段正淳」→「找段正淳」），去处后紧跟「的 / 之」的那一处只是修饰（看下一处）、开头的标点连词与趋向补语剥掉、不足两字不算；点了出路且「去」在一切别的动作（取物、出手、修习、赠予、调息、服药、打探、威逼、化解）之前即是动身——后面那件事是此行所为（「去大理城取玉璧」不是在此地取物，「服下金创药，再去剑湖宫」先做的事先算）；找移动动词前先等长遮掉「去 / 往 / 赶」的非移动义（过去的事、失去、望去、往事、以往、赶紧），「想想过去的事」「回想往事」是沉思而不是挪步；去处不在出路里的移动照抄原话交给规则驳回、不带此行所为；点名不在场景里的东西照抄原话交给规则驳回

依赖说明
- 本层的 LLMClient 抽象也被 infrastructure 的播种管道与厂商客户端引用：外层依赖内层，方向正确
- 地下城主只产出推演（ResolutionOutput；规则与气运产出 Proposal）：定案永远是领域的 resolution.settle → stakes.settle_any，推不出区间内结局的推演整份作废、属性与时钟逐项钳位；它在命令侧玩家锁里同步调用，只为自由文本回合发言（胜负未定或挂着时钟）；点选回合由 FortuneResolver 确定性地取值，不花钱，也不比确定性裁决更凶险，好过确定性裁决的那一格同样欠代价
- 一回合至多三次大模型调用（意图 + 地下城主 + 叙事）：点选回合只有叙事，结果已定的文本回合只有意图与叙事（眼前挂着时钟时加地下城主一次，只许动时钟、事实、名望）；唯一的例外是地下城主不合契约时的一次重采样（LLMResolutionAgent attempts=2，仍在 LLM_RESOLUTION_BUDGET 之内）
- 选项是 (玩家状态, 快照) 的纯函数：点选时重算即可核验，不需要任何会话缓存，多进程部署天然一致；焦点与恩怨都由事件折叠进 PlayerState，不另存
- 菜单先于叙事算出：叙事只拿到「标签（why）」作端倪（<hooks>），选项的意图永远不进提示词；菜单变了叙事才可能变，叙事从不反过来影响菜单
- 世界心跳的此地之物（时辰、人群约数、此地的事、痕迹还剩多久）只有一种写法：narrator 的 when / cast / headcount / lingering / activity / trace / crowd / chronological，briefs/scene 借用——说书人与地下城主看到的此地之物不会各执一词
