# application/
> L2 | 父级: engine/app/CLAUDE.md

应用层：用例编排。它把命令翻成领域调用、把获准之举的物理边界交给一席裁决（文本在胜负未定或挂着时钟时请地下城主推演、点选在胜负未定时交给气运）、把事件推给投影、先算菜单再把快照与端倪交给大模型渲染，
自身不含业务规则（规则与可裁区间在 domain/rules/、domain/combat.py、social.py、covert.py、stakes.py）。
对外边界是 bus.py：命令进、回合消息的异步流出；对内只依赖 domain 的端口与本层的 LLMClient 抽象。

成员清单
ports.py: LLMClient 抽象（complete 一次性补全 + 带默认实现的 stream 流式补全）与 JsonSchema 别名；端口上没有任何写世界的方法
bus.py: 命令 SpawnPlayer / ResumePlayer（quiet：只重新接上，不复述此景、不调大模型）/ SubmitText / ChooseOption，回合消息 SessionOpened / TurnResolved（意图 + 事实白描，先于叙事送达）/ NarrationDelta / TurnCompleted（全文、选项、PlayerStatus、game_over），PlayerStatus 只有语义标签（境界、伤势 health、武学写作「北冥神功（略有小成）」），另有 bonds（Bond{name, attitude, cause}）与 pursuits（Pursuit{label, note}）两栏、眼前的暗流 clocks（ClockInfo{name, kind, progress, maximum}，至多 4 只，id 与挂处不下发）与名望 renown（语义标签），缺省为空，旧客户端照读；CommandHandler 抽象与 CommandBus（按命令类型分派，重复注册即报错）
handlers.py: TurnPipeline 一回合的完整生命周期——命令侧持弱引用玩家锁：重放事件流 → 自愈投影 → 快照（版本与位置须与聚合一致）→ 死者在解析前即拒 → [Parse] → [Validate] rules.envelope 圈出物理边界（三路赌注或 FIXED，驳回为 None）→ [Resolve] 一席裁决 AdjudicationSlot.resolve(env, before, state, intent, said, clicked=…)：自由文本在胜负未定或此景挂着时钟时请地下城主推演、点选（ChooseOption 处理器传 clicked=True）在胜负未定时交给气运、其余谁也不请 → [Event] Player.decide 携提议过闸定案（resolution.settle：推出结局、钳位、补足代价、时钟坍缩）、乐观并发追加（时钟四事件 / FactEmerged / RenownChanged 一并入账）→ 同步投影图谱；推演到叙事只有入账之物一条路：白描进 turn_resolved 与 <settled_facts>，新快照的 clocks / emerged 进 <clocks> / <emerged>，没有散文旁路；重伤夺路而逃（Moved.fleeing）的回合把交手前的快照经 NarrationRequest.fled 交给渲染器；查询侧：新快照 → 记忆召回（两路、原话优先：原话 + 玩家名一路，焦点实体 + 在场者本名一路）→ TurnResolved（facts 滤掉空串白描）→ [Options] 先于叙事算出，narrator.hooks(菜单) 作端倪经 NarrationRequest.hooks 交给说书人 → [Render] 流式叙事 ∥ 记忆写入 → TurnCompleted（状态栏的人情 / 心事两栏：status.referenced 列出要取名的 id，快照与交手前快照之外缺的名字一回合只向 reader.labels 取一次；眼前的暗流 status.clocks(快照) 与名望 status.renown(状态) 随状态栏下发）；出生点按 crc32(player_id) 确定性分配或按名指定；四个处理器只决定"意图从哪来"（自由文本经解析器，选项按当前快照重算后核验 id，不经大模型）；记忆召回各多取一倍再按字面去重；续前缘与出手共用玩家锁（续上的必是落账之后的局面），quiet 续接不复述、不调大模型，只回选项与状态（断线重连、选项过期）；在场者的恩怨缘由（PlayerState.attitude_causes）经 NarrationRequest.causes 交给渲染器；死者伤势栏写「气绝」
intent_parser.py: 三道防线——WorldviewGuard 词表在调用大模型之前判 INVALID（刻意不收单字「枪」）、提示词要求大模型对违背世界观者判 INVALID、规则只认图谱实体；IntentParser 模板方法（守卫 → 解读 → 对产出的指称与话题 target / item / skill / topic 再守卫，两道检查都先剔除撞上禁词的场景正名 scene_names 与 WorldviewGuard.for_canon 收录的原著撞词正名——原著的「金针渡劫」在哪儿都不被「渡劫」误杀）；INTENT_SCHEMA 只有形状（domain/intent 不写 docstring），说明全在 INTENT_SYSTEM：LEARN 涵盖入门与精进、REST 调息疗伤独立成动作（练功疗伤以疗伤为准）、USE 服药敷药（服药疗伤以 USE 为准）、七种手段与九种所图各一句判据（「用于 / 见于」由 approach 兼容表生成，表一改提示词跟着改）、topic 话题指称（说话的对象不进 topic）、撂话离场是 MOVE（话只化进笔墨）；场景词表的人物带称号与别名、已会武学带火候；LLMIntentParser 带场景词表与输入转义、结构化输出、重采样后兜底 INVALID、LLMError 透传（回合不写任何事件）；HeuristicIntentParser 离线动词 + 关键词 + 场景词表解析：手段按 借势 > 人情 > 武力 > 计谋 > 潜行 > 言辞 认关键词并经 _fit 按兼容表退回寻常（偷袭是出手不是潜行）、打探的话题取中心词且须经 rules.ground 落得了地（落不了地只是闲谈）、威逼是 TALK×武力（点名对方手里的东西即讨要）、劝 / 说和 / 赔罪是言辞化解、服 / 敷 / 吃 + 点名之物是 USE（先于调息）、开口要他人之物是言辞讨要、引号里的话不算动作、借势的靠山不是说话的对象、人与物取最先点名者；调息疗伤先于修习判定，但句中有在场之人与出手动词时是出手——「趁龚光杰调息偷袭他」；点名不在场景里的东西照抄原话交给规则驳回
options/: 动态选项生成器（显著性菜单）包，地图见 options/CLAUDE.md——五类候选源（Thread 换个手段 / Person 一人身上的诸般招 / Ground 地上可携之物与疗伤之药 / Self 静观调息修习 / Exit 出路）经 rules.adjudicate 过滤，措辞按意图哈希挑变体，P0 的打分与席位全保留（MMR 冗余改为累加），同一对象至多两席，每席带 why（≤12 字）与风险档（risk_of(rules.stakes)，确定之事稳妥）；门面 `from app.application.options import ActionOption, OptionCategory, OptionGenerator` 不变
narrator.py: NarrationRequest（夺路逃离的交手现场 fled、在场者的恩怨缘由 causes、本回合菜单的端倪 hooks）、hooks(options)（选项 → 「标签（why）」，至多 HOOKS_MAX=4 条，按结构化 Protocol 只认 label / why）、hard_prompt（fled_scene / truth_snapshot（含 <clocks> 眼前的叙事时钟「名称｜种类｜挂在谁（玩家写你）｜进度/阈值｜满则：…」与 <emerged> 此世推演出的微观事实，空则不出现）/ known_facts / settled_facts / memories / hooks / player_input，在场者带称号与外显人设「好…；恶…；心事…」、玩家带伤势与武学火候，每个插值逐值转义，clk: / emg: id 从不露出；<known_facts> 只放 known=True 的见闻，known=False 的见闻是打探的标的，绝不进任何提示词）、NARRATOR_SYSTEM（只渲染不裁判、不得引入快照之外的人物物功地、玩家声称持有却不在行囊与武学里的东西根本不存在、举止合乎伤势、不写数值（时钟进度也不写成数字）；铁律 1 / 2 / 5 许 <hooks> 作端倪露在场面里，不许写成已发生的结果、不许替玩家行动、不许列成选项或向玩家发问；铁律 1 许 <clocks> 只作暗流——气氛与端倪，不写满、不替它坍缩，只有 <settled_facts> 明写「……满了」才算发生；<emerged> 可照应不可推翻）、LLMNarrator 流式、TemplateNarrator 离线白描、FallbackNarrator（主渲染失败：一字未出则整段白描，已出半截则补断语与白描）；地下城主的散文速写 <gm_sketch> 已废，由入账的 FactEmerged 取代；铁律经真实整局实测补强（没有「来到某地」就仍在原地、facts 之外的变化不写、行囊里的东西没易手就仍在身上、不照抄标签词），在场者武学带类别、人物行在态度之后附「恩怨：…」；夺路而逃的回合交手现场另作 <fled_scene>
resolution_agent.py: 地下城主（语义物理引擎的神经层）——Resolution(proposal: ResolutionOutput | Proposal | CombatProposal | None, by：规则 / 地下城主 / 气运)、Resolver 抽象 resolve(env, scene, state, intent, said)、CanonicalResolver（空提议）、GM_SYSTEMS / gm_system(route)（推理层：属性碰撞分析 → 量级评估 → 代价计算 → 时钟操作与状态收敛四步顺序 + 与 domain/resolution 闸门逐条一致的法则（结局由属性推出、暗流只许软结局且须挂钟、气血 / 名望 / 旁人人情的钳位、时钟上限与坍缩表、等价交换记账、微观事实禁字、路由）+ 每路一段路数（出手沿用 v3 的境界 / 性情 / 死亡判定）+ 一个只有〈〉占位的格式示例 example()——具体的人名与措辞写进示例，模型会照抄（实测时钟名与满则如何一字不差），测试填实值证明这个格式过得了闸门）、LLMResolutionAgent(llm, *, attempts=2, budget, canon_names)（不 contested 又无时钟不花钱；宽容解析：枚举认中文也认英文名、多余字段忽略、推理段截断、坏的单条时钟指令丢弃；不合契约重采样、仍不行空提议；LLMError / 超时（LLM_RESOLUTION_BUDGET 管整场）/ 意外一律空提议不抛错；事实预筛：点了原著名录里却不在此景的名字即丢）、FortuneResolver（点选回合的气运，只看 Envelope：种子 sha256(玩家 | 对象 | 尝试次数)，canonical 60% / 好一格 25% / 差一格 15%，差一格落进 GRAVE 留在 canonical，出手扣减在 safe_band 里取；FIXED 或不 contested 空提议）
adjudication.py: 一席裁决 AdjudicationSlot(resolver, fortune).resolve(env, scene, state, intent, said, *, clicked)——env 为 None（驳回）→ None；点选：env.contested 交给气运（关掉为 None），否则 None（点选从不为时钟请人）；文本：env.contested 或此景挂着时钟（scene.clocks）→ 地下城主一次；其余 None，零调用
briefs/: 地下城主简报包——输入层 XML 简报（意图 / 物理快照 / 玩家状态 / 赌注 / 物理边界）与输出层 schema，地图见 briefs/CLAUDE.md；只用 T=0 事实，foreshadow 与未知见闻正文永不进
chronicle.py: describe(event, labels, player_name) 事件 → 一句确定性白描（夺路而逃写作「夺路逃离某地，来到某地」；人情五档各有措辞，敌视「心生敌意」/ 戒备「心存戒备」/ 漠然「不再放在心上」/ 友善「生出好感」/ 信赖「深为信赖」；交涉「以言辞向某人求艺，对方口风已松」、见闻「从某人处打听到「…」」、用物「以某物疗伤」、暗中取物「以潜行暗取某人的某物——未能得手，好在无人察觉」；服药那条 HealthChanged(source="item") 白描为空串（ItemConsumed 已说了服药）；语义物理引擎六事件：ClockStarted「暗流：钟灵的戒心（1/4）」、ClockAdvanced「…渐深（3/4）」/ 回退「…稍解（1/4）」、ClockCollapsed「…满了：识破你的手脚」、ClockCleared「…烟消云散」、FactEmerged 照录原文、RenownChanged「某某的名声更响了 / 坏了几分（缘由）」；时钟事件自带名称与进度，不回查时钟表、从不露 clk: id，零步推进与零点名望为空串；调用方一律滤掉空串）；供 TurnResolved.facts、叙事的 settled_facts 与长线记忆语料共用——记忆里只存白描不存散文，幻觉进不了记忆（推演只以闸门放行、入了账的白描进记忆）；titled「段延庆（恶贯满盈）」与 known_arts「北冥神功（略有小成）」是称呼与火候的唯一写法，状态栏、Hard Prompt 与战况简报共用
projections.py: ProjectionCoordinator——publish 同步投影图谱（强一致：下一步裁决依赖它）、heal 检查点落后则从事件流追平、超前则抹去重放、chronicle 尽力写入长线记忆（失败只记日志）、rebuild 运维用整体重建两份投影；记忆写入滤掉白描为空串的事件；rebuild 取名时跳过自带名称的 clk: / emg: id
status.py: 状态栏附栏纯函数——referenced(state) 列出需取名的 id（非漠然者 + 前三条线索的对象与标的，见闻 id 一律不取，正文连名字表都不进）、bonds(state, snap, names) 人情一栏（态度非漠然者，在场者优先、再按 |rank| 降序、再按 id，至多 6 条，缘由取 attitude_causes）、pursuits(state, names) 心事一栏（新者在前至多 3 条，「求艺 · 晓风拂柳」式标签——打探只写对象「打探 · 左子穆」绝不写见闻正文，note「口风已松；已试：言辞；须友善」）、clocks(snap) 眼前的暗流（快照召回的时钟，凶险的在前、离坍缩近的在前、再按 id，至多 CLOCKS_SHOWN=4 只，只给名称 / 种类 / 格数）、renown(state) 名望的语义标签；handlers 一回合一次 reader.labels、两次调用，世界不变则逐字不变
__init__.py: 包标识

依赖说明
- 本层的 LLMClient 抽象也被 infrastructure 的播种管道与厂商客户端引用：外层依赖内层，方向正确
- 地下城主只产出推演（ResolutionOutput；规则与气运产出 Proposal）：定案永远是领域的 resolution.settle → stakes.settle_any，推不出区间内结局的推演整份作废、属性与时钟逐项钳位；它在命令侧玩家锁里同步调用，只为自由文本回合发言（胜负未定或挂着时钟）；点选回合由 FortuneResolver 确定性地取值，不花钱，也不比确定性裁决更凶险，好过确定性裁决的那一格同样欠代价
- 一回合至多三次大模型调用（意图 + 地下城主 + 叙事）：点选回合只有叙事，结果已定的文本回合只有意图与叙事（眼前挂着时钟时加地下城主一次，只许动时钟、事实、名望）；唯一的例外是地下城主不合契约时的一次重采样（LLMResolutionAgent attempts=2，仍在 LLM_RESOLUTION_BUDGET 之内）
- 选项是 (玩家状态, 快照) 的纯函数：点选时重算即可核验，不需要任何会话缓存，多进程部署天然一致；焦点与恩怨都由事件折叠进 PlayerState，不另存
- 菜单先于叙事算出：叙事只拿到「标签（why）」作端倪（<hooks>），选项的意图永远不进提示词；菜单变了叙事才可能变，叙事从不反过来影响菜单
