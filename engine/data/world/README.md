# data/world/

原著播种的产物（由 `python -m app.seed` 生成，**入库**；原著全文本身永不入库）：

- `blueprint.json` —— 原著蓝图，也是图谱的正典：抽取与写图之间的中间表示，可人工审阅后再 `apply`（Neo4j 与内存图谱都只是它的投影）
- `seed.cypher` —— 由蓝图确定性生成的写图脚本，可交给 cypher-shell（含正典节点与人群 (:Swarm) 的约束，以及运行期覆盖层 Clock / Emerged / Activity / Trace / Rumor 的 (world, id) 约束与 world 索引）
- `report.txt` —— 组装报告：丢弃（泛称 / 描述性称呼 / 悬空引用）、封存（门径落不了地的武学）、孤儿（被武学引用却下落不明的物品）、
  时间线（被 T=0 之后的事件否决的开篇状态）、自愈（孤儿的推断安放）、审计（T=0 审计的覆盖率与每处偏离缺省的结论）、
  掌故（每条人设、见闻与人群及其出处、作答者）、抽取失败的文本块
- `healing.json` —— 自愈缓存（有孤儿被安放时才出现）：每条推断的安放、理由与推断者；`assemble` / `extract` 零费用自动套用
- `audit.json` —— T=0 审计缓存（首次 `audit --ingest` 之后出现）：`{version, fingerprint, relations, characters, items}`，
  每条结论名字已落成 id、带作答者 `by`；人物结论另记作答时的原描述 `was`（原描述一变即作废），到场结论带出处 `evidence {ref, quote}`。
  版本（`tlbb-audit-v2`）或蓝图指纹（只覆盖审计不改的骨架）不符整体作废；
  蓝图带着审计痕迹（非开篇的 era、后文剧情、后来才到场、物性）而这份缓存缺失、损坏或作废时，`audit` 与 `heal` 拒绝运行——先 `assemble` 出未审的底本
- `lore.json` —— 掌故缓存（首次 `lore --ingest` 之后出现）：`{version, fingerprint, personas: [{persona, by}], facts: [{fact, by}], swarms: [{swarm, by}]}`，
  provenance 一律是推断（版本 `tlbb-lore-v2`）。指纹覆盖名字、所在、武学、关系与其 era、物性——审计改了 era 或物性，掌故整体作废、蓝图上的掌故随之清空；
  人群是向后兼容的新作答类型：没有 `swarms` 的旧缓存照读为空，人群不进指纹，版本因此不递增
- `cache/<提示词版本>/` —— 逐块抽取记录（按提示词版本 + 文本哈希命名，内容是名称级的结构化记录而非原文，
  与本块原文共享 ≥16 字的描述已清空）：中断后重跑不重复花钱；组装器改了规则，凭缓存零费用重新组装

本项目的原著抽取、图谱自愈、T=0 审计与掌故一律由 Claude 子代理经 `export` / `ingest`（`heal` / `audit` / `lore` 的 `--export` / `--ingest`）完成，
不调用付费大模型（`audit` / `lore` 连 `--use-llm` 都没有）；
缓存里早期由 Gemini 抽取的记录（v4 全部、v5 前 16 块）只留作溯源。

v5 时代的三处已知缺陷在 v6 里的去向：

- **主键歧义**：段延庆前九回多以「恶贯满盈」出场，v5 按票数让称号篡位成正名。v6 主键为 `chr:段延庆`，称号「恶贯满盈」「青袍客」「天下第一恶人」，别名「延庆太子」；

- **时间线坍缩**：v5 的人物武学取全切片并集，段誉开篇即身负北冥神功、凌波微步。v6 抽取员把第五回前后的习得写进 events，段誉 T=0 武学为空、身在剑湖宫·练武厅；
  组装器的时间线否决本次没有触发（0 条）——抽取端已守住锚点，否决是纵深防御。
- **前置物品断链**：v5 的「一阳指穴道谱诀」在原文里根本不存在——那一块的抽取把钟灵的一句揣测当成了实物并挂成一阳指的门槛，违反"只抽本段明写之事"。

  （天龙寺在本切片无路可通，不是可达候选），Neo4j 里随之多出一条 `BELONGS_TO {provenance: 推断}`。

复现入库的蓝图（需把原著放进 `data/source_text/`，不调用大模型）。当前代码的抽取提示词已是 `tlbb-extract-v7`（据 2026-10 真实 Gemini 实测改了四处措辞：
本名只要出现过一次就作 name、T=0 所在不在本段即填 null、门槛与获取地点只记原文写明的、events 也记转述与"已身负"的证据），
入库的这份蓝图出自 v6 缓存，复现须指明版本：

```bash
python -m app.seed assemble --prompt-version tlbb-extract-v6 --max-chunks 40
```

写入 Neo4j 时，换蓝图务必加 `--reset`：MERGE 只增不删，否则旧纪元的正典节点会混进新世界（写图后会对残留节点告警）。

```bash
python -m app.seed apply --reset
```

## 离线正典：T=0 审计与掌故（P1）

套用顺序是 自愈 → 审计 → 掌故，`assemble` / `extract` 每次组装后都零费用自动套用三份缓存；`heal` / `audit` / `lore` 不重新组装，只写回蓝图、换掉报告里自己那几节。

```bash
python -m app.seed audit --export DIR [--batch 40] [--all]          # 分批题面 audit-{relation,character,item}-NN.txt，每份自足；已审的不再出题
python -m app.seed audit --ingest F --by claude-subagent              # 过闸（有一条不合格整批拒收）→ audit.json → 写回蓝图
python -m app.seed lore --export DIR [--from 剑湖宫·练武厅] [--hops 2]  # 以一地为中心的人设、见闻与人群题面 lore-NN.txt，打印几地几人
python -m app.seed lore --ingest F --by claude-subagent               # 过闸 → lore.json → 写回蓝图
python -m app.seed audit | lore                                       # 不带参数：按缓存重新套用
```

审计闸门：名称全等（不做包含匹配）、枚举封闭（era 开篇 / 将至 / 后文，hazard 剧毒 / 有毒 / 蛊毒，use 疗伤 / 解毒 × 1~3）、
自由文本（description / foreshadow / basis）只许一行中文（不含换行、英文字母、数字与 <>`{}）、
新描述与后文剧情的专名 ⊆ 原描述的专名、险性须在原描述里有「毒」「蛊」字眼、`arrives_with`（`portent:<名>`）须有出处——
`ev:<块>#<序>`（与此人此物有涉的后文事件）或 `chunk:<块>`（切片里提到此人此物的原文块，附该块逐字 4~15 字摘句；
唯独原著一次也没用过其名的物品，如「毒信笺」，以摘句为凭）、与原著共享 ≥16 字的字段清空；T=0 描述撞上后文事件或非开篇关系的，报告里标 ⚠。
人物结论以作答时的原描述 `was` 判新鲜：原描述变了即作废、剔出缓存、重新出题。
掌故闸门：名称全等、出处落在切片里且提到此人、好恶心事与见闻只许一行中文、专名 ⊆ 蓝图专名（地名「·」两侧的简称也算）、
T=0 只认开篇的关系——不写后文才有的身故 / 所得 / 所会、不牵涉开篇之后（将至、后文）才结下的关系、后来才出现的物品不作见闻主体或 unlock 目标，
不照抄原著 ≥16 字，见闻的 unlock 须落在蓝图的一条边上、知情人须是主体本人 / 同门 / 有开篇关系边的人；牵涉后来才到场之人的见闻报告里标 ⚠。
人群（原著写了在场却没给名姓、成群出现的人：不能攀谈交手，只目睹、传话、受惊溃散）另有几条：地点名称全等，人数 3~500、惊惧阈值 1~10（越小越胆小）、
名称与平日所为各 ≤12 字且同过一行中文与专名检查，门派可空、填了须在蓝图里有人；出处原文块须提到这处地点（任一名字，或「上级·处所」的处所一侧——只提到上级不算）或其门派；
一批里同名两答即拒，同名的新答覆盖缓存里的旧答。
「蓝图外的专名」凭各版抽取记录里组装器会认作实体的人名、武学名与门派认出，地名、称号、别名与泛称不算。
后文事件与切片取自 `cache/tlbb-extract-v6/` 与 `data/source_text/` 的原著（`--evidence-version` 可换）；本地没有原著时出处无从核验，引出处的作答一律拒收。
